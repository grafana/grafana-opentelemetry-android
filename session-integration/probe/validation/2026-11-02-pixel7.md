# Pixel 7 session probe, November 2, 2026

All eight regression scenarios passed on a physical Pixel 7. Ten additional
cold process launches preserved the expected restart links and telemetry.
This is Debug-build evidence for the unreleased session probe, not validation
of the supported Grafana Android package.

## Results

| Scenario | Result |
| --- | --- |
| Fresh launch and process restart | New session linked to the last durable ID |
| Manual reset | Old end precedes linked new start; in-flight span retains its original ID |
| Process ownership | Main and worker keep independent chains; competing writer rejected |
| Damaged or future storage | Corrupt record recovered; unknown version preserved |
| Denied writes | Telemetry and reset continue without overwriting the durable record |
| Restart following denied writes | Links to the last successfully saved session |
| Buffered replay | Logs/spans retain their IDs; main does not drain worker data |
| Native abort after reset | Process terminates naturally; exactly one crash replays under the crashed session |

The final regression run retained 337 OTLP records with no collector errors.
Its source/APK hash check matched all 36 recorded inputs. The crash record was
rechecked against the original crash session and distinct recovery session.

The first regression run also passed. Before the second run, the driver cleanup
was tightened so a failed local evidence write still removes its USB forwarding
rule. A mocked failed launch plus failed final evidence write exercised that
cleanup path without executing device commands. Both runs are retained locally.

## Cold-launch observations

All ten launches reported `LaunchState: COLD`, with ten distinct PIDs and
session IDs, correct predecessor links and 90-byte persisted session records.
The final exports were rechecked for every launch and sampling case. All 36
input hashes matched; the collector retained 150 records with no errors.

| Measurement | Minimum | Median | Maximum |
| --- | --- | --- | --- |
| Whole SDK initialization, including storage setup | 101.25 ms | 118.33 ms | 139.79 ms |
| Activity Manager total launch time | 408 ms | 469 ms | 517 ms |

The setup timer brackets `DraftSessions.initialize`, not just the persistence
implementation. Records were checked after asynchronous writes completed; their
size is not a write-latency measurement. These are Debug, warm-filesystem
observations with no baseline or agreed performance threshold. They do
not close the production startup/storage-cost assessment.

## Reproduction

Build the Debug probe using the parent README, install it on the authorized
phone, and use the Python environment containing the pinned OTLP protobufs:

```sh
python3 -m venv session-integration/build/probe-python
session-integration/build/probe-python/bin/pip install opentelemetry-proto==1.38.0

"$ANDROID_HOME/platform-tools/adb" -s "$PHONE_SERIAL" install \
  session-integration/probe/build/outputs/apk/debug/probe-debug.apk

/usr/bin/caffeinate -i session-integration/build/probe-python/bin/python -u \
  session-integration/probe/verify.py \
  --adb "$ANDROID_HOME/platform-tools/adb" --serial "$PHONE_SERIAL" \
  --physical-device \
  --apk session-integration/probe/build/outputs/apk/debug/probe-debug.apk \
  --evidence session-integration/build/evidence/new-phone-regression

/usr/bin/caffeinate -i session-integration/build/probe-python/bin/python -u \
  session-integration/probe/verify.py \
  --adb "$ANDROID_HOME/platform-tools/adb" --serial "$PHONE_SERIAL" \
  --physical-device --startup-runs 10 \
  --apk session-integration/probe/build/outputs/apk/debug/probe-debug.apk \
  --evidence session-integration/build/evidence/new-phone-startup
```

Use fresh evidence directories. This run's ignored directories are
`physical-pixel7-20261102-regression-01`,
`physical-pixel7-20261102-regression-02` and
`physical-pixel7-20261102-startup-01` under `session-integration/build/evidence/`.
They hold installed APKs, input hashes, reports, OTLP records and probe-UID-only
logs. Keep raw evidence local.

The current changes passed 97 JVM tests (81 integration and 16 probe tests),
14 Python verifier tests, formatting, lint, coverage checks and Debug/Release
builds. Release was built, not run on the phone.
