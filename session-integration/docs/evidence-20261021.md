repo root using the local upstream wrapper:

```sh

  spotlessApply check assembleDebug assembleRelease koverXmlReport --max-workers=2
```

## API 35 emulator

Android 15, arm64-v8a, `replay_probe_api35`, serial `emulator-5580`.
Fingerprint: `google/sdk_gphone64_arm64/emu64a:15/AE3A.240806.043/12960925:userdebug/dev-keys`.

The [probe procedure](../probe/README.md) ran with a loopback OTLP receiver and
the default buffering intervals. All eight groups passed:

- Cold launch creates a fresh ID. Restart links to the previous durable ID,
  with one startup event and matching early logs/spans.
- Reset emits old end before new start. A span started before reset keeps the
  old ID; subsequent telemetry uses the new ID.
- Main and worker processes retain separate restart chains. A third process
  cannot acquire the main writer after an in-process duplicate was rejected.
- Corrupt records start fresh; unknown versions remain untouched.
- Denying file writes does not stop reset or telemetry.
- Restart after denied writes links to the last durable session.
- Logs and spans accepted into separate disk buffers survive process death.
  Restarting main does not drain the worker buffer. Restarting worker replays
  its own records with their original IDs.
- A real SIGABRT after reset terminates main. Restart replays one crash under
  the reset session, not the new startup session. A further launch does not
  replay it again.

The receiver captured 102 logs and 68 spans across 21 session IDs, with no
decoder errors. Source and APK hashes still matched at the end of the run.
An independent check of the exported records also matched early logs and spans
to the first session-start ID for all 17 telemetry-producing process launches.

## API 23 emulator

Android 6, arm64-v8a, `otel_ci_api23_arm64`, serial `emulator-5582`.
Fingerprint: `Android/sdk_phone_arm64/generic_arm64:6.0/MASTER/8690019:userdebug/test-keys`.

The same APK passed the first seven groups, including write denial, process
ownership and independent buffered replay. It captured 91 logs and 71 spans
across 19 session IDs, with no decoder errors. Source/APK hashes matched.
An independent export check matched early logs/spans to the first start ID for
all 15 telemetry-producing launches.

The native-crash group failed at natural process termination. SIGABRT reached
PID 3009 and debuggerd wrote a tombstone, but `/proc/3009/status` still showed
`S (sleeping)`. Debuggerd also logged `AM write failed: Broken pipe`. The driver
timed out after 45 seconds waiting for termination. It then stopped the app as
cleanup; it did not restart it and count forced cleanup as successful recovery.

Native-crash replay on this API 23 emulator remains unverified. This reproduces
the older prototype's symptom, but this run does not isolate an SDK issue from
an emulator/platform issue. No signal-handler code was changed.

## Evidence files

Each run keeps `environment.json`, `inputs-sha256.json`, `results.json`,
`otlp-records.json`, `collector-errors.json` and `logcat.txt`. Raw outputs are
retained locally under `session-integration/evidence/` and ignored by Git.
They are not uploaded or available through a GitHub link.

The final runs are `api35-final` and `api23-final`. API 23 also includes the
pre-cleanup `crash-process-status.txt`. An earlier API 35 single-process replay
run passed, but the final run adds the worker-buffer isolation assertions.
Both test installations were removed, both started emulators were stopped and
the local receiver was closed after retaining the evidence.

## Still needed

- Merged upstream APIs and an agreed preview configuration, including an
  explicit sampling choice. These tests leave the parent-based sampler unchanged.
- Physical-device storage/startup cost, release-runtime/R8 checks, full-duration
  timeout checks and hosted receiver/storage/UI validation.
- API 23 native-crash termination/replay needs a targeted follow-up. The other
  API 23 checks passing does not close that gap.
- Explicit acceptance of foreground-inactivity, sampling, metric and process
  limits. The inspected #57 discussion still contains the proposal, not acceptance.
- App-wide installation-ID first-run races remain outside this session-storage
  validation. Native stack capture and signal-handler interoperability are also
  separate from the crash-attribution check.

This evidence supports continued integration work. It does not close #57.
