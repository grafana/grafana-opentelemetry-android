## Final rerun after the directory-race fix

Copilot identified a race when two processes first create the shared session
directory. `mkdirs()` can return false because the other process got there
first. The constructor now rechecks `isDirectory` before falling back to memory.
The regression creates the directory between those checks and verifies a saved
session survives reopening. It failed on the old implementation on Robolectric
API 23 and 35, then passed with the fix. The existing non-directory failure test
still passes.

Both emulators below reran all eight runtime groups against the rebuilt,
minified Release APK. Each passed, including abort/replay under the crashed
session and no duplicate after another launch:

- `api23-release-directory-race-fix-20261022`: 51 logs and 74 spans.
- `api35-release-directory-race-fix-20261022`: 51 logs and 65 spans.

Each run covered 21 session IDs without decoder errors. An independent export
check matched early logs and spans to the first session start in all 17
telemetry-producing launches per run. All 33 recorded source/APK hashes match.
The deterministic directory interleaving is a JVM regression, not a claim that
the emulator run forced that exact race.

Both installed copies had SHA-256:
`72a4dfc0e44d2e7826edb08b0c065db611ef09fab218b50bc73832ddd44aa4e4`.

## What changed in the crash check

The original `Process.sendSignal(..., SIGABRT)` timed out again on API 23 in both
Debug and Release. Omitting the native-crash module also timed out. Each process
remained sleeping after debuggerd handled the signal. These failed controls are
retained as `api23-debug-20261022`, `api23-release-20261022` and
`api23-no-capture-20261022`; they are not passing replay evidence.

The probe now defaults to a test-only JNI call to libc `abort()`. Unlike simply
sending a signal, Android 6's [abort implementation](https://android.googlesource.com/platform/bionic/+/android-6.0.1_r81/libc/bionic/abort.cpp)
ensures termination if a handler returns. Logcat confirms `SI_TKILL`, the libc
`abort` frame and the probe JNI entry. The driver observed natural termination,
then restarted and checked one replayed native-crash event.

`AM write failed: Broken pipe` also appears in the successful abort run, so that
message alone does not explain the earlier timeout. The control shows the
signal-only failure is not specific to OTel capture; it does not prove its exact
platform cause. `--crash-mode signal` retains that original path for follow-up.
No SDK signal handler, chaining, errno, alternate stack, marker or replay code
was changed.

The updated no-capture Debug control also passed with native `abort()` in
`api23-abort-no-capture-20261022`: natural termination, linked recovery and no
native-crash event. This exercises the fixture independently of OTel capture.

## Limits and retained evidence

Raw records, installed APKs, source hashes, environment, results, process status
and logcat stay in ignored `session-integration/evidence/` directories. They
are local files, not attachments available through GitHub.
Both test installations were removed, both started emulators were stopped and
port 14318 had no listener after cleanup. The default build was restored with
native capture enabled and its checks/builds rerun.

This confirms the tested abort/replay case, not every signal, ABI or Android
device. Native stack capture, signal-handler interoperability and secondary-
process native crashes remain separate. Physical-device startup/storage cost,
full-duration timeouts and hosted ingestion/UI still need their own evidence.
The parent-based trace sampler is unchanged; this run does not establish the
proposed 100% cross-signal policy. Record accepted private-preview limits on
#57 and validate the eventual merged reset API before closing the integration.
